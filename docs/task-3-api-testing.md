## 2. The API under test

- **Base URL:** `http://localhost:3000/api`. All paths in the assignment (`POST /tasks`, …) are relative to it.
- **Authentication:** `Authorization: Bearer <token>`. The token comes from `POST /auth/login`
  (demo accounts: `demo@example.com` / `Demo123!` and `other@example.com` / `Other123!`).
- **Format:** JSON request and response bodies (`Content-Type: application/json`).
- **Ownership:** each task belongs to the user who created it. Other users get `404` for it, so
  its existence is not revealed.

### Task resource

| Field | Type | Rules |
| --- | --- | --- |
| `id` | string (UUID) | Generated by the server; ignored if the client sends it |
| `title` | string | **Required**; trimmed; 1–200 characters |
| `description` | string | Optional; at most 2000 characters; default `""` |
| `status` | string | Optional; `todo`, `in_progress` or `done`; default `todo` |
| `dueDate` | string or `null` | Optional; a valid calendar date `YYYY-MM-DD`; default `null` |
| `createdAt`, `updatedAt` | string (ISO 8601) | Set by the server. `updatedAt` changes on every update. |

**Error body:** every error has the same shape, so clients and tests can rely on it.

```json
{
  "error": "VALIDATION_ERROR",
  "message": "Request validation failed.",
  "details": [{ "field": "title", "message": "Title is required." }]
}
```

## 3. Expected status codes and responses

### POST /tasks – create a task

```http
POST /api/tasks
Authorization: Bearer 3f6c…
Content-Type: application/json

{ "title": "Buy milk", "status": "todo", "dueDate": "2026-12-24" }
```

```http
HTTP/1.1 201 Created
Location: /api/tasks/31e59b56-a0c8-4a98-b6b9-ec2e3c2f93a6
Content-Type: application/json; charset=utf-8

{
  "id": "31e59b56-a0c8-4a98-b6b9-ec2e3c2f93a6",
  "title": "Buy milk",
  "description": "",
  "status": "todo",
  "dueDate": "2026-12-24",
  "createdAt": "2026-11-21T18:23:53.100Z",
  "updatedAt": "2026-11-21T18:23:53.100Z"
}
```

| Scenario | Status | `error` |
| --- | --- | --- |
| Valid payload (all fields, or only `title` → defaults applied) | **201 Created** + `Location` header | – |
| Title missing / blank / longer than 200 / not a string; unknown status; invalid due date | **400 Bad Request** | `VALIDATION_ERROR` (+ `details` per field) |
| Malformed JSON | **400 Bad Request** | `INVALID_JSON` |
| Body is not a JSON object (e.g. an array) | **400 Bad Request** | `VALIDATION_ERROR` |
| `Content-Type` is not `application/json` | **415 Unsupported Media Type** | `UNSUPPORTED_MEDIA_TYPE` |
| No token, or an invalid / expired token | **401 Unauthorized** + `WWW-Authenticate: Bearer` | `UNAUTHORIZED` |

### GET /tasks/{id} – retrieve a task

| Scenario | Status | Body |
| --- | --- | --- |
| The task exists and belongs to the caller | **200 OK** | The task (same representation as above) |
| Well-formed UUID, but no such task | **404 Not Found** | `NOT_FOUND` |
| Another user's task | **404 Not Found** | `NOT_FOUND`: the task's existence is not revealed |
| The id is not a UUID (e.g. `not-a-uuid`) | **400 Bad Request** | `INVALID_ID` |
| No token / invalid token | **401 Unauthorized** | `UNAUTHORIZED` |

### PUT /tasks/{id} – update a task

PUT is a **full replacement**: the body is validated like POST, and optional fields that are
left out are reset to their defaults. `id` and `createdAt` never change; `updatedAt` is refreshed.

| Scenario | Status | Body |
| --- | --- | --- |
| Valid payload | **200 OK** | The updated task |
| Invalid payload | **400 Bad Request** | `VALIDATION_ERROR`; the stored task is unchanged |
| Task not found, or another user's task | **404 Not Found** | `NOT_FOUND`; nothing is changed |
| Not a UUID | **400 Bad Request** | `INVALID_ID` |
| No token / invalid token | **401 Unauthorized** | `UNAUTHORIZED` |

### DELETE /tasks/{id} – delete a task

| Scenario | Status | Body |
| --- | --- | --- |
| The task exists | **204 No Content** | Empty. A later `GET` returns 404. |
| Already deleted / never existed / another user's task | **404 Not Found** | `NOT_FOUND`; another user's task is not deleted |
| Not a UUID | **400 Bad Request** | `INVALID_ID` |
| No token / invalid token | **401 Unauthorized** | `UNAUTHORIZED` |

**General:** an unsupported method on a known path (e.g. `PATCH /tasks/{id}`) returns
`405 Method Not Allowed` with an `Allow` header; unknown paths return `404`.

## 4. Test suite design

| Building block | Purpose |
| --- | --- |
| **Playwright `APIRequestContext`** | HTTP client with `baseURL`, default headers, request tracing and the same reporting as the UI tests. No browser is started for the `api` project. |
| **API object model** (`src/api/tasks-api.ts`, `auth-api.ts`) | One method per endpoint. The methods return the raw response, so each test asserts the status code and body itself. Paths are relative (`tasks`, not `/tasks`), so a base path such as `/api/v1` is kept. |
| **Fixtures** (`src/fixtures/api-fixtures.ts`) | The login runs **once per worker** (`demoSession`), and the authenticated, second-user, anonymous and invalid-token clients are injected. `createdTask` provides existing data. |
| **Automatic cleanup** | The client remembers every task it created and deletes them after each test, so test data never leaks between tests. |
| **Contract assertions** (`src/utils/api-assertions.ts`) | `expectTaskContract` checks the **exact field set** and the types (UUID, ISO timestamps, enum, nullable date), which would also catch an internal field such as `ownerId` leaking. `expectError` checks the status, the error code and the invalid fields. |
| **Test data factory** (`src/data/task-factory.ts`) | Valid payloads with unique titles, so parallel workers never collide. Tests override only the field that matters. |
| **Data-driven negative tests** | 8 invalid payloads in one table, including the 200/201 character boundary, and a 4 × 2 authentication matrix (every endpoint × missing/invalid token). |
| **Read-back verification** | After POST, PUT and DELETE the test reads the resource again, so the status code alone is never trusted. |

**Coverage summary (48 tests):**

| Area | Tests |
| --- | --- |
| POST /tasks | 16 (positive 5: incl. defaults, trimming, 200-char boundary, server-managed fields; negative 11: 8 invalid payloads, malformed JSON, array body, 415) |
| GET /tasks/{id} | 4 (200, 404, 400 malformed id, 404 for another user) |
| PUT /tasks/{id} | 5 (200 + persisted, full-replacement defaults, 400 unchanged, 404, another user's task unchanged) |
| DELETE /tasks/{id} | 4 (204 + gone, second delete 404, 404, another user cannot delete) |
| Authentication matrix | 8 (4 endpoints × no token / invalid token) |
| Lifecycle | 1 (create → read → update → delete → 404, as `test.step`s) |
| POST /auth/login | 10 (200 + token contract, case-insensitive email, 401 wrong password, identical 401 for an unknown email, another account's password rejected, 400 × 4, token grants access) |

## 5. Sample code per endpoint

Excerpts from [`tasks.api.spec.ts`](../playwright-tests/tests/api/tasks.api.spec.ts). Status
codes, error codes, test data and assertion messages are constants at the top of the file, so a
change in the contract means a one-line change in the tests.

The read-back checks (a GET right after POST, PUT and DELETE) are immediate on purpose, without
`expect.poll`: the API answers only once the change is stored, so a stale read would be a bug, not
a timing issue. Polling would only be right for an eventually consistent backend (a queue, a cache
or a search index), and there it would re-send the request until the expected state appears.

### POST /tasks

```ts
test('creates a task: 201, Location header and the stored representation', { tag: '@smoke' }, async ({ tasksApi }) => {
  const payload = buildTask(CUSTOM_FIELDS);
  const response = await tasksApi.create(payload);
  expect(response.status()).toBe(CREATED_STATUS);
  const task = await response.json();
  expectTaskContract(task);
  expect(task).toMatchObject(payload);
  expect(task.createdAt, ASSERTION_MESSAGES.newTaskTimestampsEqual).toBe(task.updatedAt);
  const location = response.headers()['location'];
  expect(location, ASSERTION_MESSAGES.locationPointsToTask).toMatch(new RegExp(`${TASKS_PATH}/${task.id}$`));
  const readBack = await tasksApi.get(task.id);
  expect(readBack.status()).toBe(OK_STATUS);
  expect(await readBack.json()).toEqual(task);
});

for (const { scenario, payload, invalidFields } of INVALID_PAYLOADS) {
  test(`rejects ${scenario} with 400 VALIDATION_ERROR`, async ({ tasksApi }) => {
    const response = await tasksApi.create(payload);
    await expectError(response, BAD_REQUEST_STATUS, VALIDATION_ERROR_CODE, invalidFields);
  });
}
```

### GET /tasks/{id}

```ts
test('returns 200 and the task', { tag: '@smoke' }, async ({ tasksApi, createdTask }) => {
  const response = await tasksApi.get(createdTask.id);
  expect(response.status()).toBe(OK_STATUS);
  const task = await response.json();
  expectTaskContract(task);
  expect(task).toEqual(createdTask);
});

test("returns 404 for another user's task (no data leak)", async ({ otherUserTasksApi, createdTask }) => {
  const response = await otherUserTasksApi.get(createdTask.id);
  await expectError(response, NOT_FOUND_STATUS, NOT_FOUND_CODE);
});
```

### PUT /tasks/{id}

```ts
test('replaces the task: 200 with the new state, which is persisted', { tag: '@smoke' }, async ({ tasksApi, createdTask }) => {
  const changes = buildTask(REPLACEMENT_FIELDS);
  const response = await tasksApi.update(createdTask.id, changes);
  expect(response.status()).toBe(OK_STATUS);
  const updated = await response.json();
  expectTaskContract(updated);
  expect(updated).toMatchObject({ ...changes, id: createdTask.id, createdAt: createdTask.createdAt });
  expect(Date.parse(updated.updatedAt), ASSERTION_MESSAGES.updatedAtMovesForward).toBeGreaterThan(
    Date.parse(createdTask.updatedAt),
  );
  const readBack = await tasksApi.get(createdTask.id);
  expect(await readBack.json()).toEqual(updated);
});
```

### DELETE /tasks/{id}

```ts
test('deletes the task: 204 with an empty body, then GET returns 404', { tag: '@smoke' }, async ({ tasksApi, createdTask }) => {
  const response = await tasksApi.delete(createdTask.id);
  expect(response.status()).toBe(NO_CONTENT_STATUS);
  expect(await response.text()).toBe(EMPTY_BODY);
  await expectError(await tasksApi.get(createdTask.id), NOT_FOUND_STATUS, NOT_FOUND_CODE);
});
```

### Authentication matrix

```ts
for (const { endpoint, call } of PROTECTED_CALLS) {
  test(`${endpoint} without a token returns 401`, async ({ anonymousTasksApi }) => {
    const response = await call(anonymousTasksApi);
    await expectError(response, UNAUTHORIZED_STATUS, UNAUTHORIZED_CODE);
    expect(response.headers()['www-authenticate']).toBe(EXPECTED_AUTH_SCHEME);
  });
}
```

One pitfall found while building the suite: `request.post(url, { data: '<string>' })` with a JSON
content type sends the string **JSON-encoded again**, so a malformed body arrives as a valid JSON
string. The malformed-JSON test therefore sends a `Buffer` (see `TasksApi.createRaw`).

## 6. Running the suite

```bash
cd playwright-tests
npm ci
npm run test:api                             # starts the API automatically; no browser needed
npx playwright test --project=api --grep @smoke
API_URL=https://staging.example.com/api npm run test:api   # against another deployment
npm run report                               # HTML report with every request and response
```
